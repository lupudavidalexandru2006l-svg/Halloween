# QA 2026-11-20: bug sweep (Studio, solo)

**Verdict: GO for solo play.** Two bugs found and fixed. Trading still needs a two-player test.

Place: "Ray a pet" (placeId 140233011383258), QA save store. Before testing, every script in Studio was compared
with the repo: all 87 matched, so no Studio-only work was at risk.

## What was tested

| Area | How | Result |
|---|---|---|
| Server start | Play, read console | Clean. `[RobuxCheck] 1 problem` is the known owner decision (critterShield, pay-to-protect) |
| Every client→server remote (38) | Exploit script: 1,648 calls with junk args (nil, NaN, inf, 5,000-char strings, tables, Instances) plus every action of Extras / Trade / Tutorial / Tester | 0 server errors, player not kicked |
| Carry → bank | TesterHook `carry` x2, walk into own pan | 2 pets banked (pets 3→5), saved |
| Thaw Machine | `ThawPet` from far away (refused), then standing at machine 1 | Refused from far away, started at the machine |
| Claim thaw | `ClaimThaw 1` | Pet came out into a free pan slot |
| Sell | `SellPets` at the Sell Booth, then the same pet twice more | Sold once for 300; repeats did nothing |
| Every popup (18) | `DevOpen` hook | 15 open cleanly. welcome / gift / pageDone error only when opened with no data, which the game never does (test-only) |
| Code read | Trade, Extras, Bomb, Tag, Freeze (aim), Data (load/save/lock), Monetization (receipts), Leaderboard (Visit), Sell, Pen (bank/thaw) | 2 bugs below; the rest holds up |

## Issues

| Id | Where | What | How bad | Status |
|---|---|---|---|---|
| CA-01 | `TradeService.execute` | A pet traded away from the pan left its slot empty (selling refills it from Storage; trading used its own removal). A pet that came in by trade sat in Storage even with free pan slots | Should fix | **Fixed:** trading now uses `PenService.removePets` (selling's path) and calls `fillEmptySlots` after pets arrive |
| CA-02 | `PenService` bank on `EnteredPen` | `bankingNow[player]` is set at the start of a bank and cleared at the end. Any error in between left it set, so that player could never bank again until they rejoined | Should fix (latent soft-lock) | **Fixed:** the bank runs in `pcall`; the flag is always cleared and the error is logged |
| CA-03 | Console | `rbxassetid://203785492 failed: Asset type does not match` (3x on join) | Small | Not in the code or any game object (searched Server and Client): it comes from the avatar or a Studio plugin, not the game |

Both fixes are synced into Studio and were play-tested (banking ran through the new code).
